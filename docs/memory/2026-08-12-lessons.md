# Lessons learned (compounding engineering)

> Goal: each unit of work makes the **next** one easier.  
> Pattern: [Compounding Engineering](https://www.agentic-patterns.com/patterns/compounding-engineering-pattern/)  
> After non-trivial work or a user correction: **append a short lesson here**, and put standing rules in `AGENTS.md`.

One file only under `docs/memory/`. No `solutions/`, no process/planning subfolders.

---

## How to use this file

**After a feature / plan / ship / correction, add:**

1. What the agent got wrong (or what was expensive to rediscover)
2. The rule next time (imperative, one paragraph)
3. Optional: path or commit as evidence

**Also codify standing rules** into `AGENTS.md` (short bullets). That is the “prompt” layer from the pattern — not a second docs tree.

**Do not** put Superpowers plan drafts or locks here. Those live under `docs/superpowers/` (see below).

---

## Lessons

### 2026-08-12 — Ship means push

**Wrong:** Committed the v1 plan (`b3fa9b0`) and treated that as shipped. Did not `git push`. User saw `main` ahead of `origin/main`.

**Rule:** Ship / done / archive ⇒ commit → verify → **`git push origin HEAD`** → only then archive the thread. Local commit alone is not shipped. If remote is ahead: fetch + rebase; ask the user on real conflicts.

**Check:** `git status -sb` must not show `ahead of origin` after a ship request.

---

### 2026-08-12 — Multi-agent plans need one authority

**Wrong:** Parallel phase drafts disagreed (table names, DB paths, Runner types, backup shape). Oracle rejected until fixed.

**Rule:** For big plans: write a **lock** beside the plan (`docs/superpowers/plans/…-lock.md`), draft phases under `…-drafts/` if needed, assemble **one** plan under `docs/superpowers/plans/`. Put a **Canonical contracts** section in the final plan that wins over stale snippets. Run Oracle until **Approved**. Implementers follow the assembled plan + canonical section.

**This plan:** `docs/superpowers/plans/2026-08-12-personal-agent-v1.md`  
**Lock / drafts:** `…-v1-lock.md`, `…-v1-drafts/`

---

### 2026-08-12 — Keep docs simple

**Wrong:** Built `docs/solutions/{process,planning}/…` plus many memory files. Too many directories; plan drafts sat in the wrong place (`docs/memory` instead of Superpowers).

**Rule:**  
- Lessons → **one** dated file in `docs/memory/` (append here).  
- Superpowers specs/plans/locks/drafts → **`docs/superpowers/` only**.  
- Standing agent rules → short bullets in **`AGENTS.md`**.  
Do not invent parallel “solutions/process/planning” trees unless the user asks.

---

### 2026-08-13 — Verify escaped literals at the byte level

**Wrong:** A review treated JSON-escaped tool output as literal backslashes in Go raw strings, causing repeated fix rounds before the source bytes were checked.

**Rule:** When a finding depends on whether quotes are escaped, inspect the source directly with a fixed-string search or byte count before editing. Do not infer file contents from JSON-rendered diffs or tool results.

**Evidence:** Phase 3 Task 19 raw request fixture review.

---

### 2026-08-19 — Worker high-stakes review = consulting-grok-review, not built-in oracle

**Wrong:** Phase 6 worker repeatedly called the built-in `oracle` tool; it hit OpenAI usage limits (user no longer subscribes to ChatGPT), then fell back to self-review instead of dispatching `consulting-grok-review` (Task + `reviewer-prompt.md`).

**Rule:** On worker threads (and whenever high-stakes Oracle-shaped review is required):  
1. **Default to `consulting-grok-review`** — package the Oracle input contract, dispatch **Task** with `.agents/skills/consulting-grok-review/reviewer-prompt.md` filled in; require Verdict + Evidence + Smallest fix + severity.  
2. **Do not call built-in `oracle`** — no ChatGPT subscription; it fails with usage/provider limits.  
3. Do **not** substitute silent self-review for that gate.  
4. If Task dispatch itself is provider-blocked, report **BLOCKED** on the review gate explicitly; do not pretend a self-review satisfied the mandate.

**Evidence:** Phase 6 Backup worker thread; user corrections 2026-08-19.

### 2026-08-19 — consulting-grok-review via Grok thread, not Task/OpenAI

**Wrong:** `consulting-grok-review` skill says dispatch Task/subagent; Task tool routes through OpenAI and fails when ChatGPT is unsubscribed. Worker stuck or fell back to self-review.

**Rule:** For consulting-grok-review on this project: spawn a **new Amp thread in grok45 mode** with `amp --mode grok45 --no-archive-after-execute -ox -x '<prompt>'` (or equivalent), poll `amp threads markdown T-…` until `## Verdict`, then act on Critical/Important. Do **not** use the Task tool or built-in oracle. Do **not** treat self-review as the gate.

**Evidence:** Phase 6 review thread https://ampcode.com/threads/T-01a01801-6408-7553-a0d4-58af60b7885d

### 2026-08-19 — Master merge: board tip can block pure FF

**Wrong:** After Phase 7 worker branched from `99efb67`, master committed board-only `a3d8428` on `main`. `git merge --ff-only` failed even though histories only diverged on docs.

**Rule:** Prefer merge commit (or rebase worker) when main has board-only commits after the worker base. Do not force-push worker. Still require green `go test ./...` on the merge result before ship.

**Evidence:** `origin/main...origin/impl/v1-p7-hardening` was 1 board commit vs 6 phase commits; merged as `3dec9b6`.
